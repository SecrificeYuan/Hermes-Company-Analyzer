# 总体架构

## 架构目标

在 48 小时 MVP 中，将在线公开数据获取、可解释金融分析、LLM 叙述和可视化展示分开。三位成员在固定目录中并行开发，跨模块只依赖 `contracts/` 内冻结的 v1 契约。

## MVP 技术框架

| 层级 | 选择 | 负责内容 | MVP 边界 |
|---|---|---|---|
| Web 与 API | Next.js + TypeScript | 页面、Route Handlers、ECharts 图表、作业轮询 | 不在 HTTP 请求中抓取网页或调用 LLM |
| Worker | 单个 Node.js + TypeScript 进程 | 轮询 SQLite、数据获取、规范化、函数分析、LLM 叙述 | 单机单 Worker，不做并行 Worker 或高可用 |
| 持久化 | SQLite | `analysis_jobs`、短期缓存、快照索引、报告 | 仅服务演示，不承诺生产级并发能力 |
| 数据校验 | TypeScript + Zod | HTTP 输入、外部来源、快照、报告与 LLM 输入输出 | Schema 与 `contracts/` 同步维护 |
| 外部数据 | 原生 `fetch` + `DataSourceAdapter` | 官方 API、网页、开放数据、开源采集工具、社交公开内容 | 不绕过登录、反爬或平台规则 |
| LLM | `LlmProvider` 适配器 + Evidence Pack | 非结构化提取、归纳和中文解释 | 不产生事实、数值或风险等级 |
| 图表 | Apache ECharts | 趋势、构成、风险分布、时间线与来源下钻 | 样式和交互仅由前端负责 |

明确不使用 Redis、BullMQ、消息队列、额外缓存服务、微服务 RPC 或 WebSocket/SSE。

## 系统数据流

```text
浏览器
  │ POST /v1/analysis-jobs
  ▼
Next.js Route Handler
  │ 插入 SQLite analysis_jobs（queued）
  ▼
单个 TypeScript Worker 轮询并以事务领取作业
  │ resolving → fetching → normalizing → analyzing → generating_narrative
  ├── DataSourceAdapter → SourceFetchResult → CompanySnapshot
  ├── 确定性函数/规则 → 风险信号、风险等级、VisualizationSpec
  └── Evidence Pack → LlmProvider → Narrative 或 fallback
  ▼
SQLite 保存作业状态与 AnalysisReport
  │
  └── Next.js GET /jobs/{jobId}、GET /analyses/{analysisId}
       ▼
    总览、图表、时间线、证据下钻
```

## SQLite 作业协议

`analysis_jobs` 是任务状态唯一真源。最小字段为：

| 字段 | 含义 |
|---|---|
| `id` | 作业 ID |
| `company_query` | 用户输入的名称或股票代码 |
| `status` | 公开作业状态枚举 |
| `attempt` | 已领取次数，MVP 不做复杂自动重试 |
| `lease_expires_at` | Worker 领取作业后的租约到期时间 |
| `updated_at` | 最后状态更新时间 |
| `analysis_id` | 成功或部分成功时的报告 ID |
| `error_code` / `error_message` | 面向前端的失败信息 |

Worker 通过 SQLite 事务把 `queued` 或过期租约任务改为当前阶段并写入新的租约。启用 WAL 和合理 `busy_timeout`，但只允许一个 Worker 进程，避免将 SQLite 当作高并发队列。

## 模块与文件所有权

| 成员模块 | 独占目录 | 负责什么 | 不负责什么 |
|---|---|---|---|
| 数据获取 | `apps/worker/src/acquisition/`、`apps/worker/src/orchestration/` | 公司候选解析、来源适配、规范化、快照、SQLite 作业领取与阶段状态 | 风险评分、LLM 报告内容、页面与图表 |
| 数据分析 | `apps/worker/src/analysis/` | 指标函数、规则/权重、冲突处理、Evidence Pack、LLM 校验、报告与图表语义 | 网站抓取、SQLite 轮询、页面样式 |
| 结果展示 | `apps/web/` | Next.js 页面、Route Handlers、轮询、ECharts、证据下钻、空/错状态 | 抓取、风险公式、修改快照或报告 |
| 共享 | `contracts/`、`docs/` | 契约和稳定决策 | 未经三人确认不能直接修改 |

## 数据所有权

| 数据 | 所有者 | 写入者 | 读取者 | 规则 |
|---|---|---|---|---|
| 原始响应与抓取日志 | 数据获取 | 适配器 | 采集调试层 | 不进 Git，不返回浏览器 |
| `SourceFetchResult` | 数据获取 | 单一适配器 | 采集编排器 | 每个来源独立记录成功或失败 |
| `CompanySnapshot` | 数据获取 | 规范化器 | 数据分析 | 有来源、可信度、验证状态与冲突处理 |
| `AnalysisReport` | 数据分析 | 分析模块 | Route Handlers、结果展示 | 每条结论和图表都可引用证据 |
| `analysis_jobs` | 任务编排 | Route Handlers、Worker | 结果展示 | SQLite 是状态唯一真源 |

## 关键规则

### 多来源与冲突

官方来源优先于第三方和社区来源；同等级来源优先较新的披露。无法消解的字段标记为 `conflicted`，保留采用或拒绝原因，且不得参与风险评分。

社交平台内容必须标为 `opinion`、`community`，仅作为口碑观察。它不能单独形成财务、信用或最终风险判断。

### 函数量化与 LLM

函数和规则计算指标、趋势、权重和风险等级。LLM 只从带来源和验证状态的 Evidence Pack 中提取、归纳并生成中文叙述。未验证的 LLM 提取不能进入量化；任何 LLM 段落引用不存在的证据、出现输入以外的数值或将观点表述为事实时，Worker 丢弃该段并使用模板化 fallback。

### 图表语义与视觉实现

分析模块输出 `VisualizationSpec`，说明指标关系、时间范围、事件和证据。结果展示模块将其渲染为 ECharts 图表，并独占颜色、布局、交互、响应式和无障碍文本。分析模块不得输出 ECharts 配置。
