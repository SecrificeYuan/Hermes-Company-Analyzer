# PRD · 支付前风险评估：付钱之前，先拍张 X 光

> 2026-10-03 黑客松定位定稿。本文档取代"股票数据聚合平台"的旧自我认知，
> 是赛后所有功能取舍的准绳。与 [DOC-A](DOC-A-DATA-ENGINE.md)（数据引擎）、
> [DOC-B](DOC-B-ANALYSIS-ENGINE.md)（分析引擎）、[DOC-C](DOC-C-FRONTEND.md)（前端）并列，
> 术语沿用 [PUBLIC-COMPANY-DATA.md](PUBLIC-COMPANY-DATA.md)。

## Problem Statement

普通人把一笔重要的钱交给一家公司时——买股票、买理财、报培训班、办健身卡、
付加盟费、给供应商预付款——**没有任何工具能在付款前告诉他这家公司靠不靠谱**。

- 东方财富/同花顺只覆盖上市公司，且把 500 个字段摆出来，假设用户自己就是分析师；
- 天眼查/企查查覆盖非上市公司，但服务 B 端专业用户，给的是原始工商/司法档案，
  小白看不懂，也不会在办卡前想起去查；
- 结果是：现金流、诉讼、老板套现、口碑崩塌这些**隐藏状态**散落在各处，
  普通人无法提前预知。等暴雷上了热搜，钱已经没了。

普通人的钱被骗走的主战场根本不在股市——是理财爆雷、加盟骗局、培训机构跑路、
健身房预付费跑路。**健身房跑路离每个人都很近，上市公司暴雷离普通人很远。**

## Solution

**付钱之前，先拍张 X 光。**

HERMES · 公司透视是一个支付前风险评估产品：在任何一笔钱付出去之前，
用户花 60 秒输入公司名——或者直接说出自己的情况——得到一张**公司角色面板**：

- **血条/攻防** = 可见基本面（现金流、盈利、护城河——沿用现有 HP/DEF/ATK/士气）；
- **debuff 栏** = 隐藏状态（老板套现🩸、质押穿透☠️、诉讼风暴⚡、欠薪疑云、
  关店潮、无牌照🎭……），debuff 有层数、会叠加致死——这是产品的聚焦信号；
- **红/黄/绿灯** = 一句话结论"这钱能付吗"，黄灯附"怎么付更安全"
  （别办年卡改月付、加盟费分期、先查商务部备案）；
- 每盏灯可点开**证据链**：来源、访问时间、原始数据——"数据证实"是产品铁律，
  资料不足就写资料不足，绝不编造。

覆盖范围从上市公司扩展到**普通人真正会遇到的公司**：理财公司、加盟品牌、
培训机构、健身房、供应商。上市公司是高清 CT（披露数据全），
非上市公司是便携 X 光（工商/司法/投诉/备案的间接信号成像）。

首页在"搜索""筛选"之外开出**第三模式"对话"**：一个 AI 输入框，用户直接说
"我妈要买理财""我想购买 XXX 股票"。AI 是路由器+翻译官：解析支付意图、
追问澄清主体、调用原有数据平台跑信号引擎、交付面板与亮灯、用人话解释。
对话不是荐股聊天机器人——**产品本体是面板和灯，对话只是把小白带过来的路**。

## User Stories

1. 作为非专业付款人，我想在付款前输入公司名立刻看到红/黄/绿灯，以便 60 秒内决定要不要付。
2. 作为非专业付款人，我想直接用大白话说出我的情况（"我妈要买理财"），以便在不知道公司全名、不懂金融术语的情况下开始一次评估。
3. 作为非专业付款人，当我说的情况里没有明确公司主体时，我希望 AI 追问我一两句（哪家公司/哪个品牌），而不是猜一个答案给我。
4. 作为非专业付款人，我想看到公司像游戏角色一样的面板（血条、攻击、防御），以便零金融知识也能一眼看出它"能不能打"。
5. 作为非专业付款人，我想看到 debuff 栏里每个隐藏状态的图标和一句人话解释（"老板正在质押 80% 的股份——历史上这是暴雷前最常见的剧本"），以便知道危险具体是什么。
6. 作为非专业付款人，我想看到 debuff 的层数（质押 30%→60%→80% 逐层升级）和叠加警告（多个 debuff 同时出现=濒死），以便判断危险的严重程度。
7. 作为非专业付款人，当结果是黄灯时，我想看到"怎么付更安全"的具体建议（改月付、分期、先查备案），以便我不必在"全付"和"不付"之间二选一。
8. 作为非专业付款人，我想评估的不只是上市公司——还有健身房、培训机构、加盟品牌、理财公司、供应商，以便覆盖我真实会付钱的所有场景。
9. 作为非专业付款人，当一家公司资料不足时，我想看到诚实的"资料不足"和缺哪块，而不是一个编出来的分数。
10. 作为非专业付款人，我想看到每盏灯背后的数据出处（来源、访问时间），以便我相信这不是 AI 在吓唬我。
11. 作为非专业付款人，我想看到"这家公司正在演的剧本历史上出现过 N 次、后来怎样了"，以便我有一杆历史参照的秤。
12. 作为非专业付款人，我想在对话里继续追问（"那这家和 XX 比呢"），以便顺着我的决策思路走完，而不是被一次性报告打断。
13. 作为专业用户，我想展开每条结论的证据链（原始数据、来源链接、信号命中明细），以便验证 AI 的判断而非盲信。
14. 作为专业用户，我想在 PRO 模式看到完整的指标密度与公告/舆情/股东网络明细，以便把 Hermes 当作尽调的第一站。
15. 作为专业用户，我想看到每个信号的判定阈值和规则出处，以便判断规则本身是否适用于我评估的这家公司。
16. 作为演示评委，我想看到一个真实暴雷案例的时间回放（debuff 在暴雷前 18 个月逐个亮起），以便相信"提前亮灯率"不是嘴上说的。
17. 作为演示评委，我想现场输入任意一家我认识的非上市公司（比如某健身房）并看到合理的评估与诚实的资料缺口，以便验证这不是只能演固定案例的玩具。
18. 作为首次访问者，我想在首页三模式（搜索/筛选/对话）中一眼理解各自用途，以便 10 秒内开始第一次评估。
19. 作为回访用户，我想看到我的最近搜索/最近对话记录，以便继续上次的决策。
20. 作为所有用户，我想看到明确的免责与边界声明（历史统计不代表未来、不构成投资建议、回报率保持 null），以便我对产品有正确的信任预期。

## Implementation Decisions

### 形态与入口

- 首页 `queryMode` 从 `'search' | 'filter'` 扩展为 `'search' | 'filter' | 'chat'`；
  第三模式"对话"摆放一个 AI 输入框，占位符示例即用户原话（"我妈要买理财""我想购买 XXX 股票"）。
- 对话模式是**入口与路由器**，不是新产品：最终交付物仍是报告页/角色面板
  （`CharacterCard`/`HealthBar`/`HiddenStatusList`/`EvidenceDrawer` 全部复用），
  对话负责把人带到这里并用人话解释。
- 品牌名保留 HERMES · 公司透视，不新增口号；预警与亮灯语义融入现有面板，
  不改变 LITE/PRO 双模式架构（开关仍仅在报告页）。

### 对话管线（新增）

- 新增对话 API 路由，管线为：**意图分类 → 主体识别 → 澄清追问 → 路由 → 叙事生成**。
  - 意图分类：支付场景七类——买股票 / 买理财 / 加盟 / 报班培训 / 办卡预付费 /
    供应商预付 / 其他。意图决定加载哪些品类专属信号。
  - 主体识别：从自然语言中提取公司/品牌名，走现有 `/api/suggest` → `/api/search`
    语义（唯一准确命中才进入报告，否则给候选让用户核对——沿用，不另造匹配逻辑）。
  - 澄清追问：无可靠主体时必须追问，禁止猜测主体后生成评估。
  - 路由：上市公司走现有 `/report/[id]` + X-Ray 契约；非上市主体走
    `CompanyIdentity` / `CompanyHealth` 健康评估入口 + 新增非上市信号层。
  - 叙事生成：正式接入 `analysis/verdict.ts` 预留的 LLM hook，输入为
    面板数据+命中信号+证据出处，输出为人话结论。LLM 只做翻译，不做数据生产；
    所有数字必须来自数据平台，叙事层不得出现无出处的断言。
- LLM 调用置于环境变量配置的 hook 之后，未配置时回退到现有模板诊断——
  对话模式在无 LLM 环境下依然可用（话术降级为模板）。

### 信号引擎扩展（lib/analysis 纯函数层）

- 沿用铁律：`lib/analysis` 不 import 网络/fs，输入输出只认 `lib/types.ts`。
- 现有 5 条 debuff 规则（老板套现/质押穿透/诉讼风暴/供应商反水/欠薪疑云）
  对非上市主体保持适用，输入字段缺失时规则不触发（与"资料不足"语义一致）。
- 新增**跨品类通用红灯信号**（输入来自新适配器，见下）：
  诉讼缠身/被执行、经营异常/行政处罚、老板跑路前兆（法人频繁变更、减资、股权出质）、
  口碑崩塌（投诉量趋势）、欠薪信号。
- 新增**品类专属弹药**：
  - 加盟品牌：商务部商业特许经营信息管理平台备案查询——**未备案而招商加盟，本身即红灯**；
  - 理财公司：金融牌照核验——无相应牌照而向公众募资，致命 debuff；
  - 预付费品类（健身/培训）：成立时长、参保人数与开店速度的比值、大额折扣预售行为，
    组合为"跑路前奏"剧本。
- **剧本库**：前奏剧本 = 信号组合 + 历史案例结局统计。黑客松范围人工整理
  3–5 个真实案例（培训机构、健身房、理财爆雷、A 股暴雷各一），
  结局统计用真实公开数据，标注"历史不代表未来"。
- 亮灯判定：绿/黄/红三档，阈值与现有 `overallRisk` 三档语义对齐；
  "叠加致死"规则：致命 debuff（无牌照/未备案招商）任一命中即红灯，
  非致命 debuff 叠加数 ≥3 升级一档。

### 数据层（新增非上市适配器）

- 合规红线沿用现有立场：不绕过登录、验证码、429 与 robots；来源失败显示状态，
  不用模拟企业兜底，不宣称覆盖完整工商名录。
- **爱企查自动读取受限**（PUBLIC-COMPANY-DATA.md 已实测：匿名搜索返回空 pageData、
  robots 禁止 `/*ajax`），不得作为实时自动来源；黑客松演示所用的非上市案例数据
  走**人工采集快照**（来源与采集时间随证据链一并展示），这与现有"过程缓存+来源标注"
  语义兼容。
- 可直接程序化接入的来源优先：商务部特许经营备案平台（直接查询）、信用中国
  （经营异常/失信）、黑猫投诉（投诉量趋势）。国家企业信用信息公示系统有验证码，
  黑客松阶段人工查询（10 家量级可行）并留存截图/快照。
- 所有新适配器沿用现有超时与降级模式（单源超时返回 null、6s 总时限、
  `meta.sources` 记录 ok/fallback），切片缺失不阻塞面板渲染。

### 合规与诚实边界（继承并强化）

- 不输出买卖建议、不预测收益、回报率保持 `null`；历史剧本统计必须标注
  "历史不代表未来"。对话模式下 AI 被用户要求荐股时，礼貌拒绝并重定向到风险评估。
- 评估结论措辞为"可见信号"层面（沿用"公告标题统计不等于司法案件全貌"
  式的诚实边界），重大决策提示继续尽调。

## Testing Decisions

好的测试只测外部行为：给定一份公司数据，断言面板/亮灯/debuff 输出；
给定一句自然语言，断言意图、主体与路由结果——不断言内部实现。

- **纯函数层（主 seam，唯一新 seam）**：`lib/analysis` 新增的非上市信号规则、
  品类专属弹药、叠加致死规则，全部以 fixture 输入做单测。沿用 DOC-B 的
  mock 三档模式，新增非上市 fixture（如 mock-gym-danger / mock-franchise-unfiled /
  mock-wealth-unlicensed），并给出预期亮灯基线表；改动算法后复测不劣化，
  且原有 mock-healthy/warning/danger 三档回归必须通过。
- **对话管线**：意图分类与主体识别用固定用例集（"我妈要买理财""我想购买 XXX
  股票 100 股""帮我看看 XX 健身"）做断言测试，LLM 以 stub 替代；
  澄清追问路径（无主体输入）必须有用例。测试挂在新对话 API 路由这一最高 seam 上，
  不穿透到数据平台内部（数据平台响应以 fixture 替代）。
- **叙事层**：模板回退路径（无 LLM）有快照测试；LLM 路径只断言
  "输出中的数字均能在输入数据中找到出处"这一性质，不断言具体措辞。
- 验证命令沿用：`npm run typecheck`、`npm run test`、`npm run build`，
  及 DOC-B 的三档 curl 复测。

## Out of Scope

- 荐股、买卖点建议、收益预测、任何形式的回报率输出；
- 实时行情、交易功能、账户/持仓同步（"持仓透视"留作赛后路线）；
- 监控与推送（盯梢模式：用户已否决为低频）；
- 全品类全量工商名录覆盖（黑客松只做演示案例所需的十家量级主体）；
- 爬虫对抗：不绕过验证码/登录/反爬的任何工程投入；
- 侦探解谜游戏、暴雷 Boss 战回放的完整产品化（演示中用 1 个真实案例
  手工搭建时间回放即可，不做通用时间机器）。

## Further Notes

- **演示脚本（约 4 分钟）**：痛点数字（健身房跑路/培训暴雷/理财爆雷）→
  对话模式输入"我妈要买理财"→ 追问澄清 → 面板亮红灯+证据链 →
  加盟无备案弹药（商务部备案查询页现场查）→ 切上市公司暴雷案例，
  时间回放 debuff 在暴雷前 18 个月逐个亮起 → 收口：
  "东财给你数据，天眼查给你档案，Hermes 给你一盏灯。"
- **差异化三句话**：东财/同花顺=给数据（只覆盖上市、假设你是分析师）；
  天眼查/企查查=给原始档案（服务 B 端专业用户）；Hermes=给灯
  （普通人、支付前 60 秒、游戏语言、结论+证据）。
- 评委可能的攻击点与应答：
  - "和 ChatGPT 有什么区别？"——通用大模型没有我们的实时数据管道与信号引擎；
    AI 只做翻译，数字全部来自数据平台且挂出处。
  - "你的信号准吗？"——历史案例回放就是回测；我们呈现的是可见信号与历史统计，
    不预测未来。
  - "数据哪来？"——全部免费公开来源，合规边界写进产品（资料不足就是资料不足）。
- 赛后路线（不在本 PRD 范围）：持仓透视（组合隐藏关联）、通用时间机器、
  扫码合同/门店招牌唤起评估、天眼查/企查查授权 API 接入。
