# 数据源适配器契约（v1，已冻结）

## 目的

数据获取面对官方 API、公告网页、开放数据、开源采集工具和社交平台等异构来源。任何新来源都必须通过 `DataSourceAdapter` 接入，禁止把特定网站的字段、Cookie、HTML DOM 或错误格式泄漏给数据分析和结果展示模块。

## 适配器接口

实现语言为 TypeScript。开源采集工具、脚本或 SDK 通过一个薄适配器转换为以下逻辑接口；它们不需要改动后续模块。

```ts
type SourceQuery = {
  requestId: string;
  company: { name: string; stockCode: string; market: "A_SHARE" };
  categories: SourceCategory[];
  timeRange?: { start?: string; end?: string };
};

interface DataSourceAdapter {
  readonly manifest: SourceManifest;
  fetch(query: SourceQuery, signal: AbortSignal): Promise<SourceFetchResult>;
}
```

`fetch` 必须将预期的来源失败编码为 `failures`，而不是让整个作业因一个站点超时而抛出未处理异常。仅编程错误或基础设施故障可以抛出异常，由 Worker 归类为作业失败。

## 输入、输出与来源元数据

- `SourceQuery`：由公司解析阶段提供规范化企业身份，适配器不能自行把同名企业静默替换为另一家公司。
- `SourceFetchResult`：见 `source-fetch-result.v1.schema.json`。它返回原子 `records`、每项来源元数据和独立 `failures`。
- `SourceRecord`：记录可结构化数据、文本或链接，但不跨模块传递完整原始响应。大型原文或 JSON 只允许保存受控的本地 `rawRef`，不得返回给浏览器。
- 采集编排器负责将多个 `SourceFetchResult` 去重、统一时间与单位，并产出 `CompanySnapshot v1`。

## 来源类型与可信度

| `sourceType` | 典型来源 | 默认 `reliabilityTier` | 可作为什么依据 |
|---|---|---|---|
| `official_api` | 交易所、公司、监管方公开 API | `official` | 财务、公告、监管和企业事实 |
| `official_web` | 交易所公告页、公司官网、政府公开页 | `official` | 财务、公告、监管和企业事实 |
| `open_data` | 合规开放数据集、公开数据服务 | `third_party` | 需与来源声明一起使用 |
| `web_page` | 媒体或机构公开网页 | `third_party` | 新闻与经营观察，不能覆盖官方披露 |
| `social_platform` | 公开社交平台内容 | `community` | 只能作为舆情/口碑观察 |

`extraction.method` 为 `structured_api`、`html_parser`、`open_source_tool`、`llm_assisted` 或 `manual_import`。`llm_assisted` 必须提供 `extractionConfidence` 和 `verificationStatus`，并在进入分析前经规则或人工字段校验。

## 合规与安全边界

1. API 密钥、Cookie、登录态只从环境变量读取，不能写入 Git、日志、快照或 API 响应。
2. 不绕过登录、验证码、付费墙、访问频率限制或平台服务条款；来源不可用时返回失败状态。
3. 只获取完成本项目所需的公开企业信息。社交内容只保存必要摘录和公开链接，不收集或展示用户敏感个人信息。
4. 网页和社交文本均是不可信输入。它们不能作为程序指令传给 LLM，必须以数据字段和引用摘录形式封装。
5. 适配器 Manifest 必须写明来源名称、类别、支持数据项、访问方式和已知限制，便于替换来源和评估覆盖范围。
6. `exchange_announcement` 规范化到报告层时一律映射为 `announcement`；来源 `reputation` 一律保留为 `reputation`。
7. 规范化器按“官方来源优先、同等级较新披露优先”选择字段。无法消解时写入 `conflicted` 决策，保留原因且令该数据 `scoreEligible: false`。

## 验收要求

- 给定相同的规范化企业身份，适配器输出应可被 Schema 校验。
- 单一来源超时、限流或字段缺失时，其他来源仍可继续，最终作业转为 `partial` 而不是崩溃。
- 每条写入快照的数值、事件或观察都有至少一个来源记录。
- 社交来源的记录必须同时有 `sourceType: social_platform` 和 `claimKind: opinion`。
